# pvetty — Translations

pvetty uses a tiny gettext-like mechanism (`lib/i18n.sh`): the English text
written in the code **is** the translation key.

```bash
T "Shutdown"                     # REPLY = "Shutdown" or its translation
Tf "VM %s - Start" "$vmid"       # translated printf format
```

Menu labels (`view_menu`), table headers (`view_table`), section titles
(`c_section`), key/value labels (`c_kv`, `cfg_line`), toolbar labels, key
hints and dialog titles/texts are translated automatically by the helpers.

## Where the translations come from

For a language `<code>`, a string is looked up in this order:

1. `lang/<code>.sh`: the strings of pvetty (messages, task descriptions,
   dialogs...);
2. the **official catalog of the Proxmox VE web interface**,
   `/usr/share/pve-i18n/pve-lang-<code>.js` (package `pve-i18n`, installed on
   every node): menu labels, table headers, options... get **exactly the words
   of the web UI**, for the 34 languages of the GUI, and follow the installed
   Proxmox VE version (`lib/i18n-pve.pl` reads it, ~60 ms at start-up);
3. English.

Fully translated languages (`lang/*.sh` + catalog, about 93 %; the rest are
names such as ZFS, SPICE or Windows versions, kept in English): **French,
Spanish, German, Chinese (simplified), Russian**. The other languages of the
web UI are available with the catalog alone (12 to 51 % depending on the
language).

## Language selection

`language = auto` (default) uses, in this order:

1. the locale (`LC_ALL`, `LC_MESSAGES`, `LANG`) when it is not English
   (`fr_CA.UTF-8` → `fr`, `zh_CN.UTF-8` → `zh_CN`);
2. the language of the datacenter (Datacenter › Options › Language, in
   `/etc/pve/datacenter.cfg`), like the web UI;
3. English.

Force a language with `--lang fr`, `language = fr`, `PVETTY_LANGUAGE=fr` or
`F4` › Language (the list shows every available language).

## Double width characters

Chinese, Japanese and Korean characters take two cells in a terminal. For
these languages (`zh*`, `ja`, `ko`), the text widths are computed in cells
(`vlen`, `fit`, `dwidth` in `lib/widgets.sh`); the other languages keep the
faster character count. Right-to-left scripts (Arabic, Hebrew, Persian) are
not laid out correctly by most terminals: their catalog is used, but expect a
poor display.

## Language files

`lang/en.sh` is the reference: it only defines formats because the source
strings are already English. A language file defines:

```bash
LANG_NAME="Français"                 # shown in the language menu
DATE_FMT='%Y-%m-%d %H:%M:%S'         # strftime format of dates
DATE_SHORT='%d/%m %H:%M:%S'          # short format (task lists)
L=(
    ["VM %s - Start"]="VM %s - Démarrer"
    ["Start"]=""                     # empty = Proxmox VE catalog, then English
)
```

It only needs the strings that the Proxmox VE catalog does not translate (an
entry of the file wins over the catalog).

Rules:

- keep printf placeholders (`%s`, `%d`) **in the same order** (no `%1$s`:
  bash printf does not support positional arguments);
- keep translations short enough for buttons and column headers;
- an empty translation falls back to the catalog, then to English.

## Adding or completing a language

```bash
tools/i18n-check.sh                     # coverage of every language
tools/i18n-check.sh -v it               # strings of Italian still in English
tools/i18n-extract.sh > lang/it.sh      # template with every source string
$EDITOR lang/it.sh                      # set LANG_NAME, translate what -v listed
tools/i18n-check.sh it                  # coverage and placeholder check
pvetty --lang it
```

`lang/TEMPLATE.sh` is the pre-generated template.

## Updating a language after code changes

```bash
tools/i18n-extract.sh > lang/TEMPLATE.sh
tools/i18n-extract.sh lang/fr.sh > lang/fr.sh.new && mv lang/fr.sh.new lang/fr.sh
tools/i18n-check.sh -v fr
```

Existing translations are kept, new strings are added empty, and strings no
longer used disappear.

## For developers

- Write user-visible strings in English in the code and pass them through `T`,
  `Tf` or one of the helpers listed above.
- Do not build sentences from fragments; use a format string:
  `Tf "Remove snapshot '%s'?" "$name"`, not `"Remove snapshot" + name`.
- Reuse the wording of the web UI when it exists: the string then comes
  translated from the Proxmox VE catalog.
- Values coming from the API (names, statuses, configuration values) are not
  translated, except statuses passed through `fmtv status` (`running`,
  `stopped`...), which may be translated like any other string.
- Measure displayed text with `vlen` / `dwidth` and cut it with `fit`, not
  with `${#var}` (double width characters).
- Run `tools/i18n-extract.sh` to check that a new string is detected, and the
  screen tests in other languages (`tests/screens/scenarios`, `name@code`).
