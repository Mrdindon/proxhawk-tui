# Proxhawk-tui — текстовая консоль для Proxmox VE

[English](README.md) | [Français](README.fr.md) | [Español](README.es.md) | [Deutsch](README.de.md) | [简体中文](README.zh-CN.md) | **Русский**

Версия 2.2.1 · лицензия AGPL-3.0-or-later

`proxhawk-tui` — текстовая версия веб-интерфейса Proxmox VE (GUI на порту
8006). Она воспроизводит его компоновку, навигацию и большинство панелей с
помощью рамок Unicode, графиков из символов Брайля, значков Nerd Font и
цветов ANSI и не требует ничего, что не установлено на узле Proxmox VE.

## Основные возможности

- **Та же компоновка и те же меню, что и в веб-интерфейсе** (проверено по
  определениям меню Proxmox VE 9): верхняя панель, дерево ресурсов (виды
  Сервер / Папка / Пул / Хранилище), меню навигации по объекту, панель
  инструментов, панель содержимого и панель *Задачи / Журнал кластера*.
- **Чтение и запись**: в каждой таблице конфигурации есть
  *Добавить / Изменить / Удалить* (`a` / `e` / `d`). Диалоги **создаются по
  схеме API** вызова, который они выполняют: они предлагают те же
  параметры, варианты и значения по умолчанию, что и диалоги GUI, включая
  строки свойств (`net0`, `scsi0`, `rootfs`...), редактируемые во вложенных
  формах.
- **Весь GUI**: центр обработки данных (кластер, параметры, хранилища всех
  типов, задания резервного копирования, репликация, права, пользователи,
  токены API, 2FA, группы, пулы, роли, области, HA и правила привязки, SDN
  с зонами, VNet, подсетями, контроллерами, IPAM, DNS, файрволом VNet,
  фабриками, картами маршрутов, списками префиксов, ACME, файрвол, серверы
  метрик, сопоставления ресурсов и каталогов, пользовательские модели ЦП,
  уведомления), узел (сеть с применением/откатом, сертификаты и заказы
  ACME, DNS, hosts, время, службы, обновления, репозитории, диски с
  GPT/очисткой, LVM, LVM-Thin, каталог, ZFS, **Ceph** с мастером установки,
  мониторы, OSD, CephFS, пулы), ВМ и контейнеры (оборудование/ресурсы,
  cloud-init, параметры, снимки, резервные копии, восстановление, файрвол,
  права, HA, клонирование, шаблон, миграция).
- **Консоль**: `qm terminal` для ВМ с последовательным портом, **SSH для
  Linux-ВМ без последовательного порта** (IP определяется через гостевой
  агент, таблицу соседей или сканирование сети моста), `pct enter` для
  контейнеров, оболочка узла.
- **Минимальные требования**: чистый bash + Perl и `pvesh` из состава
  Proxmox VE. Для диалогов — `whiptail` (тоже в составе) или `dialog`. Нет
  демона, нет зависимостей, ничего не записывается за пределами
  `~/.config/proxhawk-tui` и временного каталога.
- **Быстро**: небольшой постоянный помощник на Perl загружает API один раз
  и отвечает за миллисекунды, вместо запуска `pvesh` (1–2 с) при каждом
  чтении.
- **Протестировано**: `tools/integration-test.sh` проходит каждую панель и
  каждое действие на реальном узле и проверяет каждую запись через API (см.
  [docs/TESTING.md](docs/TESTING.md)).
- **Модульно**: каждая панель — небольшая функция в `views/`; темы, наборы
  значков и языки — обычные файлы.
- **Клавиатура и мышь**, 256 цветов, truecolor или 8 цветов, значки Nerd
  Font, Unicode, чистый ASCII или без значков. Сочетания клавиш и цвета
  настраиваются; десять тем (Dracula, Nord, Gruvbox, Catppuccin, Tokyo
  Night...).
- **34 языка**: английский, французский, испанский, немецкий, китайский
  (упрощённый) и русский полностью; остальные языки GUI — через
  официальный каталог Proxmox VE, установленный на узле (те же слова, что и
  в GUI). См. [docs/I18N.md](docs/I18N.md).
- **Пакетные действия и очередь**: отметьте гостей клавишей `Пробел` в
  таблицах поиска, чтобы запустить, остановить или сделать их резервную
  копию вместе; действия над занятым гостем ставятся в очередь.
- **Для скриптов**: `proxhawk-tui guests list -o table`,
  `proxhawk-tui guests start 101`, `proxhawk-tui api get /version`...
  (вывод в JSON или таблицей, см. [docs/CLI.md](docs/CLI.md)).
- **Плагины**: дополнительные пункты меню (установщик community-scripts,
  инвентарь Ansible) — см. [docs/EXTENDING.md](docs/EXTENDING.md#plugins).

## Требования

| Компонент | Примечания |
|-----------|-------|
| Узел Proxmox VE 7, 8 или 9 | запускать от `root` на узле, напрямую или через `sudo` (см. [Кто может запускать](#кто-может-запускать)) |
| bash ≥ 4.3 | стандартно |
| perl + Perl-модули PVE | входят в Proxmox VE |
| `whiptail` или `dialog` | `whiptail` установлен по умолчанию; иначе встроенные запросы |
| `less` | необязательно, для просмотра журналов |
| Терминал UTF-8, ≥ 80×18 | рекомендуется 256 цветов; для оригинальных значков нужен Nerd Font |

## Установка

### Одной командой (пакет последней версии)

На узле Proxmox VE от root (или через `sudo`) одна команда устанавливает
последнюю версию (`.deb` проверяется по сумме SHA-256 перед установкой
через `apt`):

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/Mrdindon/proxhawk-tui/main/install.sh)"
proxhawk-tui
```

Через sudo: `sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/Mrdindon/proxhawk-tui/main/install.sh)"`,
затем `sudo proxhawk-tui`.

Удаление: `apt remove proxhawk-tui`. Перед запуском можно прочитать
[install.sh](install.sh); пакеты также есть на
[странице релизов](https://github.com/Mrdindon/proxhawk-tui/releases).

### Через git clone

Ветка `main` содержит выпущенные версии (теги `vX.Y.Z`); `develop` — текущая
разработка.

```bash
apt install git            # если git ещё не установлен
git clone https://github.com/Mrdindon/proxhawk-tui.git /opt/proxhawk-tui
cd /opt/proxhawk-tui
./proxhawk-tui             # запуск на месте, или:
./install.sh               # команда "proxhawk-tui" (ссылка в /usr/local/bin)
```

- **Обновление**: `proxhawk-tui upgrade` (см. [Обновление](#обновление)).
- **Конкретная версия**: `git checkout vX.Y.Z` (вернуться к последней: `git checkout main`).
- **Удаление**: `./install.sh --uninstall`, затем удалить каталог.
- Подходит любой каталог; `./install.sh --prefix DIR` размещает команду не в
  `/usr/local/bin`.
- Не смешивайте оба способа: удалите пакет (`apt remove proxhawk-tui`) перед
  использованием клона, или наоборот.

### Обновление

```bash
proxhawk-tui upgrade --check    # есть ли новая версия? (код возврата 10, если есть)
proxhawk-tui upgrade            # обновить (запрашивает подтверждение; --yes, чтобы пропустить)
```

`upgrade` определяет, как был установлен proxhawk-tui:

| Установлен | Что делает `upgrade` |
|---|---|
| командой установки (пакет `.deb`) | скачивает `.deb` последней версии, проверяет сумму SHA-256 и устанавливает его через `apt` (от root или через `sudo`) |
| через `git clone` | `git fetch`, показывает новую версию и её коммиты, затем `git pull --ff-only` текущей ветки (отказывает при локальных изменениях) |
| из архива, распакованного вручную | показывает доступную версию и как её установить |

`--version X.Y.Z` устанавливает конкретную версию (пакет). Повторный запуск
команды установки тоже обновляет пакет.

### Кто может запускать

proxhawk-tui напрямую использует локальный стек API Proxmox VE, как `pvesh`
(без HTTP и без тикета): на узле он должен работать от **root**, напрямую
или через `sudo`. **Права Proxmox VE** — отдельный уровень: при запуске
proxhawk-tui спрашивает, от имени какого пользователя Proxmox VE работать
(`root@pam`, `alice@pve`...), и применяются права этого пользователя, как в
GUI (см.
[Running as another user](docs/CONFIGURATION.md#running-as-another-user)).
Для запуска proxhawk-tui из учётной записи Linux без прав root нужен доступ
к API по HTTPS с токеном: пока не поддерживается.

Полезные параметры:

```bash
proxhawk-tui --glyphs nerd       # значки Font Awesome из GUI (нужен Nerd Font
                                 # в ВАШЕМ терминале, см. docs/CONFIGURATION.md)
proxhawk-tui --theme dark        # оформление «Proxmox Dark»
proxhawk-tui --lang ru           # язык интерфейса (по умолчанию: автоматически)
proxhawk-tui --select qemu/100   # открыть сразу ВМ 100
proxhawk-tui --backend pvesh     # не использовать постоянный помощник API
```

## Основные клавиши

| Клавиша | Действие |
|-----|--------|
| `↑` `↓` / `j` `k`, `PgUp` `PgDn`, `Home` `End` | перемещение в активной панели |
| `Tab` / `Shift+Tab` | следующая / предыдущая панель (дерево → меню → содержимое → задачи) |
| `←` `→` | свернуть / развернуть в дереве, переход между панелями |
| `Enter` | открыть / выполнить действие над выбранной строкой |
| `/` | поиск ресурсов |
| `v` | сменить вид дерева (Сервер, Папка, Пул, Хранилище) |
| `a` `e` `d` | Добавить, Изменить, Удалить в таблицах конфигурации |
| `s` `h` `c` `H` `m` | Запуск, меню Выключения, Консоль, SSH, Ещё (гости) |
| `b` `h` `S` `B` | Перезагрузка, Выключение, Оболочка, Массовые действия (узлы) |
| `t` | сменить период графиков в сводках |
| `l` | переключить *Задачи* / *Журнал кластера* |
| `r` / `F5` | обновить |
| `F1` / `?` | окно справки: клавиши текущей панели |
| `F2` `F3` `F4` | кнопки верхней панели: Создать ВМ, Создать CT, меню пользователя (настройки, значки, язык...) |
| `Пробел` `m` `f` | отметить гостя, пакетные действия, фильтр (таблицы поиска) |
| `w` | URL консоли в браузере (noVNC / xterm.js) для гостя или узла |
| `F6` | приостановить / возобновить автообновление |
| `q` / `F10` | выход |

Полный список — в [docs/USAGE.md](docs/USAGE.md).

## Ограничения

- Графические консоли (noVNC, SPICE) нельзя показать в терминале: вместо них
  используются последовательная консоль, SSH или `pct enter` (`w` даёт URL
  консоли noVNC для браузера).
- Работает только на узле кластера (удалённого подключения к API пока нет).
- proxhawk-tui работает от `root` на узле кластера (напрямую или через
  `sudo`): он напрямую использует локальный стек API (без HTTP и без
  тикета), точно как `pvesh`; применяются права Proxmox VE пользователя,
  выбранного при запуске.
- Загрузки (ISO, шаблоны, сниппеты) берут файл с самого узла.
- На консоли Linux самого узла (экран/клавиатура, IPMI) Nerd Font
  использовать нельзя: proxhawk-tui загружает там собственный консольный
  шрифт (значки и графики, при выходе восстанавливается прежний);
  китайский, японский, корейский и языки с письмом справа налево на этой
  консоли заменяются английским. См.
  [docs/CONFIGURATION.md](docs/CONFIGURATION.md#linux-console).
